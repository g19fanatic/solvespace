# Finding 09: Edge Detection and Selection in SolveSpace

## Summary

This document covers how SolveSpace identifies "edges" of a solid (the SShell/SSurface
boundaries), what data structures represent them, and how edge/face selection works in the UI.
This is critical for chamfer/fillet design because the user must select which edge to chamfer
or fillet.

---

## 1. Edge Data Structures in the B-Rep Layer

### SCurve (src/srf/surface.h)

An **SCurve** is the fundamental B-rep edge. It separates exactly two surfaces:

```cpp
class SCurve {
public:
    hSCurve         h;          // handle
    hSCurve         newH;       // new handle after Boolean copy
    enum class Source : uint32_t { A=100, B=200, INTERSECTION=300 };
    Source          source;

    bool            isExact;    // true if exact NURBS curve available
    SBezier         exact;      // the exact NURBS curve (if isExact)

    List<SCurvePt>  pts;        // piecewise linear approximation

    hSSurface       surfA;      // one surface on each side
    hSSurface       surfB;      // the other surface
    ...
};
```

Key properties:
- Every SCurve MUST have exactly two surfaces (surfA and surfB) — invariant for watertight shells
- `isExact` flag distinguishes exact NURBS edges from PWL-approximated intersection curves
- The exact representation is an SBezier (rational polynomial curve)
- pts[] is the piecewise-linear approximation used for rendering

### SShell::curve (src/srf/surface.h)

The shell contains all its curves:
```cpp
class SShell {
public:
    IdList<SCurve,hSCurve>      curve;    // B-rep edges
    IdList<SSurface,hSSurface>  surface;  // B-rep faces
    bool                        booleanFailed;
    ...
};
```

### STrimBy (src/srf/surface.h)

This defines how a surface is trimmed by a curve:
```cpp
class STrimBy {
public:
    hSCurve     curve;       // which curve
    bool        backwards;   // direction of traversal
    Vector      start;       // start of trim segment
    Vector      finish;      // end of trim segment
};
```

Each surface has a `List<STrimBy> trim` that defines its boundary curves.

### SEdge and SEdgeList (src/polygon.h)

For display purposes, edges are converted to a simpler form:
```cpp
class SEdge {
public:
    int    tag;
    int    auxA, auxB;   // auxiliary data (e.g., style, face ID)
    Vector a, b;         // endpoints
};

class SEdgeList {
public:
    List<SEdge>     l;
    ...
};
```

The `SShell::MakeEdgesInto(SEdgeList *sel)` method converts all SCurves to SEdges for rendering.

### EdgeKind (src/polygon.h)

The SKdNode::MakeCertainEdgesInto function uses EdgeKind to classify edges for display:
```cpp
enum class EdgeKind : uint32_t {
    NAKED_OR_SELF_INTER  = 100,  // error: edge not shared by exactly 2 triangles
    SELF_INTER           = 200,  // self-intersecting mesh
    TURNING              = 300,  // silhouette/outline edge (normal turns)
    EMPHASIZED           = 400,  // marked for special display
    SHARP                = 500,  // dihedral angle > threshold (crease edge)
};
```

**SHARP** edges are the most important for chamfer/fillet: they are edges where two faces
meet at a non-tangential angle — precisely the edges that get chamfered/filleted.

**TURNING/EMPHASIZED** edges are display artifacts for silhouette rendering.

## 2. How Edges Are Generated for Display

### From B-Rep Shell (NURBS path)

In `Group::GenerateDisplayItems()` (src/groupmesh.cpp), the display outlines are generated:

```cpp
// From the B-rep shell, extract edges for display
displayOutlines.Clear();
if(SS.GW.showEdges) {
    runningShell.MakeSectionEdgesInto(...);
    // or:
    SSurface::MakeEdgesInto(...) for each surface
}
```

The `SSurface::MakeEdgesInto(SShell *shell, SEdgeList *sel, MakeAs flags)` method
converts surface trim curves to edge segments.

### From Triangle Mesh (for face selection)

The `Group::displayMesh` (an SMesh) is used for face selection via raycasting:
```cpp
uint32_t SMesh::FirstIntersectionWith(Point2d mp) const;
```
Returns the face ID (triangle meta.face value) of the first triangle hit by a screen-space ray.

The face ID corresponds to an Entity of FACE_* type in SK.entity.

## 3. Face vs. Edge vs. Curve Selection in the UI

### Three Tiers of Selectable Things

The UI distinguishes three types of selectable geometry on a solid:

1. **Curve entities** (2D sketch curves: LINE_SEGMENT, ARC_OF_CIRCLE, CIRCLE, CUBIC)
   - Always selectable as entities
   - Part of SK.entity as sketch elements
   - Used for extrude/revolve profile selection

2. **Face entities** (FACE_NORMAL_PT, FACE_XPROD, FACE_N_ROT_TRANS, etc.)
   - Generated by Group::Generate() for each face of a 3D solid
   - Represent an SSurface of a mesh group
   - Selectable when `showFaces` is enabled
   - Used in constraints like PT_ON_FACE, PT_FACE_DISTANCE

3. **"Solid edges"** (the edges between faces of a 3D solid)
   - **NO native selectable entity type exists for B-rep edges**
   - In triangle-mesh rendering, edges are display artifacts only
   - No hEntity handle exists for a solid edge

### HitTestMakeSelection (src/draw.cpp:420)

The hit testing algorithm:

```
STEP 1: Iterate all SK.entity items
  - Use ObjectPicker (canvas.Pick()) to test each entity's rendered form
  - Collect hits into hoverList with distance/zIndex/depth
  - Face entities skipped if !showFaces
  
STEP 2: Sort hoverList by zIndex (descending), then distance (ascending)

STEP 3: ChooseFromHoverToSelect() picks best candidate:
  - Respects group order (can't select entities from groups after activeGroup)
  - Returns selection with entity handle or constraint handle

STEP 4: If nothing found and showFaces is on:
  - Raycast into displayMesh using FirstIntersectionWith(mp)
  - Returns face ID (triangle meta.face) as entity handle
  - This maps to a FACE_NORMAL_PT or similar face entity
```

Key code (draw.cpp:497-513):
```cpp
if(sel.constraint.v == 0 && sel.entity.v == 0 && showShaded && showFaces) {
    Group *g = SK.GetGroup(activeGroup);
    SMesh *m = &(g->displayMesh);

    uint32_t v = m->FirstIntersectionWith(mp);
    if(v) {
        sel.entity.v = v;  // Face ID becomes entity handle
        Hover hov = {};
        hov.selection = sel;
        hoverList.Add(&hov);
    }
}
```

### GroupSelection (src/ui.h:786-813)

After hit-testing selects entities, GroupSelection() summarizes the current selection:

```cpp
struct {
    std::vector<hEntity>     point;
    std::vector<hEntity>     entity;
    std::vector<hEntity>     anyNormal;
    std::vector<hEntity>     vector;
    std::vector<hEntity>     face;       // IsFace() entities
    std::vector<hConstraint> constraint;
    int         points;
    int         entities;
    int         workplanes;
    int         faces;                  // count of face entities
    int         lineSegments;
    int         circlesOrArcs;
    int         arcs;
    int         cubics;
    int         periodicCubics;
    int         anyNormals;
    int         vectors;
    int         constraints;
    int         stylables;
    int         constraintLabels;
    int         withEndpoints;
    int         n;                      // total selected items
} gs;
```

Face entities go into `gs.face[]` and `gs.faces` count. There is no `edges` or `solidEdges`
counter — **solid edges are not a first-class selectable entity type in SolveSpace**.

## 4. Face Entities (How Faces Are Made Selectable)

### FACE_NORMAL_PT and FACE_XPROD (src/sketch.h)

Face entities encode the face's normal vector:

```
FACE_NORMAL_PT  (5000): normal + point-on-face using a point entity and normal direction
FACE_XPROD      (5001): normal using cross product of two vectors
FACE_N_ROT_TRANS (5002): for translated (Step/Repeat) faces
FACE_N_TRANS    (5003): for translate group faces  
FACE_N_ROT_AA   (5004): for rotate group faces
FACE_ROT_NORMAL_PT (5005): for revolve/helix faces
FACE_N_ROT_AXIS_TRANS (5006): for linked/assembly faces
```

These are generated by:
- `Group::MakeExtrusionTopBottomFaces()` — top/bottom faces of an extrusion
- `Group::MakeLatheSurfacesSelectable()` — curved surfaces of a lathe/revolve

The `uint32_t SSurface::face` field stores the entity handle that represents this surface.
When `SMesh::FirstIntersectionWith()` returns a face ID, that ID IS the entity handle.

### IsFace() predicate (src/drawentity.cpp)
```cpp
bool EntityBase::IsFace() const {
    switch(type) {
        case Type::FACE_NORMAL_PT:
        case Type::FACE_XPROD:
        case Type::FACE_N_ROT_TRANS:
        case Type::FACE_N_TRANS:
        case Type::FACE_N_ROT_AA:
        case Type::FACE_ROT_NORMAL_PT:
        case Type::FACE_N_ROT_AXIS_TRANS:
            return true;
        default:
            return false;
    }
}
```

## 5. The Fundamental Problem: No Selectable Solid Edges

### Current State

SolveSpace **does not have** a selectable solid edge entity type. This is the core challenge
for implementing chamfer/fillet.

Currently:
- **Faces** are selectable (via FACE_* entity types)
- **Sketch curves** are selectable (via LINE_SEGMENT, ARC_OF_CIRCLE, etc.)
- **Solid edges (B-rep SCurves)** have no user-visible entity type

When you hover over a solid edge in SolveSpace, you see highlighted display outlines, but
clicking selects a **face** (the mesh triangle under the cursor), not the edge itself.

### Why This Matters for Chamfer/Fillet

Chamfer/fillet needs the user to select **which edge** to modify. This requires either:

**Option A: Add new EDGE_OF_SOLID entity type**
- Create Entity::Type::EDGE_OF_SOLID or similar
- Generated during Group::Generate() from SCurve data
- IsFace() returns false but IsEdge() returns true (or just test the type)
- Stored in SK.entity as group entities (like FACE_NORMAL_PT)
- Selectable via HitTestMakeSelection

**Option B: Use face pair selection**
- User selects two faces; the edge between them is the chamfer/fillet target
- More complex UX but avoids new entity types
- FreeCAD chamfer actually uses face reference: Add(d1, d2, edge, face) where face
  indicates which side gets d1

**Option C: Use adjacent face selection**
- User selects one face; the tool finds adjacent edges of that face
- Simpler UX but less precise for solids with many edges

**Option D: Synthesize edges during hit-test from the triangle mesh**
- When showEdges is on, display solid edges as highlighted line segments
- Hit-test against those segments and return a synthetic "edge ID"
- No new entity type needed; edge identified by (face1_id, face2_id) pair

### Recommended Approach for MVP (Option D/A hybrid)

For MVP, the simplest approach is to synthesize selectable edges:

1. **During display**: `SKdNode::MakeCertainEdgesInto()` with `EdgeKind::SHARP` already
   extracts creases/sharp edges from the triangle mesh for display
2. **For hit-testing**: Add edge selection by checking click proximity to displayed SHARP edges
3. **Edge identity**: An edge can be identified by the pair of face IDs it separates
   (face pair from the SEdge.auxA, auxB fields which store face/triangle info)
4. **GroupSelection**: Add `gs.solidEdge[]` and `gs.solidEdges` counter

## 6. How SEdge auxA/auxB Encode Face IDs

In `SMesh::MakeEdgesInto()` (src/mesh.cpp), solid edges are generated from triangle pairs:

```cpp
void SMesh::MakeEdgesInto(SEdgeList *sel) {
    // For each pair of adjacent triangles, test if dihedral angle > threshold
    // If so, add to the edge list with auxA = face1.meta.face, auxB = face2.meta.face
    ...
}
```

The `STriangle::STriMeta` stores:
```cpp
typedef struct {
    uint32_t face;    // entity handle of the face (maps to FACE_* entity)
    RgbaColor color;
} STriMeta;
```

So each triangle already knows which FACE_* entity it belongs to. When two triangles share
an edge, `auxA = triangle1.meta.face` and `auxB = triangle2.meta.face` encode which two
faces meet at that edge.

## 7. SKdNode Sharp Edge Extraction

The existing sharp edge extraction (used for display):

```cpp
// From polygon.h:
void SKdNode::MakeCertainEdgesInto(SEdgeList *sel, EdgeKind how, bool coplanarIsInter,
                                   bool *inter, bool *leaky, int auxA = 0) const;
```

For `EdgeKind::SHARP`, this extracts edges where adjacent face normals differ beyond a
threshold angle. These are precisely the edges visible on the display as "solid edges."

The SEdge entries produced have:
- `a`, `b`: 3D world-space endpoints of the edge segment
- `auxA`: face ID on one side
- `auxB`: face ID on other side

## 8. Group::displayOutlines (SOutlineList)

For rendering outlines, SolveSpace uses:

```cpp
class SOutline {
public:
    int    tag;
    Vector a, b;       // endpoints
    Vector nl, nr;     // normals of left and right faces
};

class SOutlineList {
    List<SOutline> l;
    ...

```

The `Group::displayOutlines` (src/sketch.h) is built by `SMesh::MakeOutlinesInto()`.
For chamfer/fillet edge selection, we'd want to work with SEdgeList (SHARP edges) rather
than SOutlineList (which includes silhouette edges that disappear when the view rotates).

## 9. Design for Edge Selection in Chamfer/Fillet

### New Entity Type Approach

A new entity type for selectable solid edges:

```cpp
// In EntityBase::Type enum (src/sketch.h):
SOLID_EDGE   = 17000,   // a selectable solid edge
```

Fields needed in the Entity:
- `numPoint`: midpoint of the edge (for selection proximity testing)
- `point[0]`, `point[1]`: handle references to the two endpoint POINT_N_COPY entities
- `param[0]`: edge ID or (face1_id << 16 | face2_id) as a compact edge identifier

Generation in `Group::GenerateDisplayItems()` or a new method:
```cpp
void Group::MakeSolidEdgesSelectable(EntityList *el) {
    // Use displayMesh to find SHARP edges
    SEdgeList sharpEdges;
    displayMesh.MakeCertainEdgesInto(&sharpEdges, EdgeKind::SHARP, ...);
    
    for(SEdge &se : sharpEdges.l) {
        // Create SOLID_EDGE entity with endpoints and face IDs
        Entity e = {};
        e.type = Entity::Type::SOLID_EDGE;
        e.group = h;
        e.numPoint = (se.a + se.b) / 2;  // midpoint
        e.param[0] = se.auxA;  // face1 entity handle
        e.param[1] = se.auxB;  // face2 entity handle
        el->AddAndAssignId(&e);
    }
}
```

HitTest modification in `draw.cpp::HitTestMakeSelection`:
```cpp
// Add after face testing:
if(showEdges) {
    // Test SOLID_EDGE entities via Entity::Draw(DrawAs::DEFAULT, &canvas)
    // or via direct line segment proximity testing
}
```

### Simpler Alternative: Edge Identified by (face1, face2) Pair

When the CHAMFER group is created:
1. User selects a face entity (existing selection)
2. The selected face's entity handle is stored in `Group::predef.entityB`
3. User then selects an adjacent face, stored in `Group::predef.entityC`
4. The chamfer/fillet is applied to the edge between face entityB and face entityC

This approach:
- No new entity type needed
- Uses existing face selection
- The edge is uniquely identified by the (face1, face2) pair
- FreeCAD uses a similar approach for chamfer

## 10. Topology Stability Problem (Toponaming)

A critical challenge: when the source group changes (e.g., extrude depth changes), the
mesh rebuilds and face entity handles may change. This is the **Toponaming problem**.

Current SolveSpace uses a REMAP mechanism (src/sketch.h Group::EntityMap remap):
```cpp
EntityMap remap;  // maps EntityKey -> EntityId across regeneration
```

For CHAMFER/FILLET:
- Face entities are remapped via REMAP constants (REMAP_TOP=1001, REMAP_BOTTOM=1002, etc.)
- New REMAP constants needed: REMAP_CHAMFER_FACE=1011, REMAP_FILLET_FACE=1012
- These ensure that "the top face" stays "the top face" even when regenerated
