## 1. The Group Abstraction

A `Group` in SolveSpace is the core modeling unit. Every solid modeling operation is a `Group`. Groups form an ordered chain; each group contributes geometry that is boolean-combined with the previous group's cumulative solid.

### Group::Type enum (src/sketch.h:181-189)
```cpp
enum class Type : uint32_t {
    DRAWING_3D          = 5000,
    DRAWING_WORKPLANE   = 5001,
    EXTRUDE             = 5100,
    LATHE               = 5101,
    REVOLVE             = 5102,
    HELIX               = 5103,
    ROTATE              = 5200,
    TRANSLATE           = 5201,
    LINKED              = 5300
};
```

**Key observation for chamfer/fillet**: New types like `CHAMFER = 5400` and `FILLET = 5401` would fit naturally here.

## 2. The Group Struct Fields (src/sketch.h:160-360)

```cpp
class Group {
    hGroup      h;           // handle/ID for this group
    Group::Type type;        // which kind of group this is
    int         order;       // position in generation order

    hGroup      opA;         // "source" group (sketch to extrude, etc.)
    hGroup      opB;         // second operand (rarely used)

    double      valA;        // general-purpose parameter (e.g., # copies in rotate)
    double      valB;        // second parameter (e.g., helix pitch)
    double      valC;        // third parameter

    struct {
        Quaternion  q;       // orientation (for workplanes)
        hEntity     origin;  // reference point
        hEntity     entityB; // reference entity (axis, workplane normal, etc.)
        hEntity     entityC; // third reference entity
        bool        swapUV;
        bool        negateU;
        bool        negateV;
    } predef;                // "pre-defined" geometric references

    Group::Subtype subtype;  // ONE_SIDED, TWO_SIDED, ONE_SKEWED, TWO_SKEWED, WORKPLANE_*

    // Boolean combination mode
    enum class CombineAs : uint32_t {
        UNION       = 0,
        DIFFERENCE  = 1,
        ASSEMBLE    = 2,
        INTERSECTION = 3
    };
    CombineAs meshCombine;   // how this group combines with prev running solid

    // Generated geometry (per-group and cumulative)
    SShell      thisShell;     // surfaces generated by THIS group
    SShell      runningShell;  // cumulative shell AFTER boolean with prev
    SMesh       thisMesh;      // fallback triangle mesh
    SMesh       runningMesh;   // cumulative mesh AFTER boolean with prev

    // Display-ready geometry
    SMesh       displayMesh;
    SOutlineList displayOutlines;

    // Error tracking
    struct { PolyError how; ... } polyError;
    bool        booleanFailed;

    // Remap table: maps (hEntity, copyNumber) -> EntityId
    EntityMap   remap;
};
```

### For Chamfer/Fillet
The `predef.entityB` field would store the **target group handle** (the group whose solid is being chamfered). The `valA` field would store the **chamfer distance** or **fillet radius**. `meshCombine = CombineAs::DIFFERENCE` would be used for the chamfer cut (see below).

## 3. Group::Generate() — Entity Generation Phase (src/group.cpp:388-800)

`Generate()` creates **logical entities and parameters** from the group definition. It does NOT create geometry — it creates the parametric skeleton.

### What each group type does in Generate():

#### DRAWING_3D / DRAWING_WORKPLANE
- Creates a WORKPLANE entity (h.entity(0)), NORMAL entity (h.entity(1)), POINT entity (h.entity(2))
- No parameters added

#### EXTRUDE (src/group.cpp:415-455)
```cpp
case Type::EXTRUDE: {
    AddParam(param, h.param(0), gn.x);  // extrusion vector X
    AddParam(param, h.param(1), gn.y);  // extrusion vector Y
    AddParam(param, h.param(2), gn.z);  // extrusion vector Z
    // For each entity in opA group:
    //   CopyEntity(..., REMAP_BOTTOM, ..., CopyAs::N_TRANS)  // bottom copy
    //   CopyEntity(..., REMAP_TOP,    ..., CopyAs::N_TRANS)  // top copy
    //   MakeExtrusionLines(...)  // vertical edge entities
    // MakeExtrusionTopBottomFaces(...)  // face entities for selection
```
- Uses `h.param(0..2)` for the extrusion vector (3 DOF, constrained to workplane normal)
- CopyEntity duplicates every entity from opA, translating it to top/bottom positions

#### LATHE (src/group.cpp:458-494)
- No new params (axis is fixed numeric)
- Creates arc entities for each point revolved

#### REVOLVE (src/group.cpp:496-545)
- `h.param(0..2)` = axis origin (constrained to predef.origin)
- `h.param(3)` = rotation angle (free, user can constrain)
- `h.param(4..6)` = axis direction (constrained)
- Creates two copies of each entity at start/end angles

#### HELIX (src/group.cpp:547-600)
- `h.param(0..6)` same as REVOLVE
- `h.param(7)` = translation distance along axis

#### TRANSLATE / ROTATE (src/group.cpp:602-660)
- Uses `valA` for count
- Creates N copies of source entities

### For Chamfer/Fillet Generate()
A CHAMFER group's Generate() would be simple:
- `AddParam(param, h.param(0), default_distance)` — the chamfer distance
- **No entity copies needed** — the chamfer group operates on the existing solid, not on 2D sketch entities
- Possibly generate face-entity references for the chamfered faces (for constraint attachment)

## 4. GenerateShellAndMesh() — Geometry Generation Phase (src/groupmesh.cpp:212-460)

This is the critical function that creates `thisShell` (and `thisMesh` if forced) and combines it with the previous group's solid into `runningShell`.

### Full control flow:

```
GenerateShellAndMesh()
├── Clear thisShell, thisMesh, runningShell, runningMesh
├── Check for source errors (if EXTRUDE/LATHE/REVOLVE, check opA polyError)
│
├── [TRANSLATE/ROTATE] → GenerateForStepAndRepeat()
├── [EXTRUDE] → thisShell.MakeFromExtrusionOf(bezierLoops, tbot, ttop, color)
├── [LATHE]   → thisShell.MakeFromRevolutionOf(bezierLoops, pt, axis, color, this)
├── [REVOLVE] → thisShell.MakeFromHelicalRevolutionOf(...) or MakeFromRevolutionOf()
├── [HELIX]   → thisShell.MakeFromHelicalRevolutionOf(...)
├── [LINKED]  → thisShell.MakeFromTransformationOf(impShell, offset, q, scale)
│
├── thisShell.MergeCoincidentSurfaces()  [unless ASSEMBLE]
│
└── GenerateForBoolean(prevRunningShell, thisShell, runningShell, meshCombine)
    ├── UNION:        runningShell = prevShell ∪ thisShell
    ├── DIFFERENCE:   runningShell = prevShell − thisShell
    ├── INTERSECTION: runningShell = prevShell ∩ thisShell
    └── ASSEMBLE:     runningShell = prevShell + thisShell (no boolean, just merge)
```

### The EXTRUDE path in detail (src/groupmesh.cpp:248-321):
```cpp
Group *src = SK.GetGroup(opA);
Vector translate = Vector::From(h.param(0), h.param(1), h.param(2));

// tbot and ttop define the extrusion envelope
if(subtype == Subtype::ONE_SIDED) {
    tbot = {0,0,0}; ttop = translate.ScaledBy(2);
} else { // TWO_SIDED
    tbot = translate.ScaledBy(-1); ttop = translate.ScaledBy(1);
}

// For each loop set in source bezierLoops:
thisShell.MakeFromExtrusionOf(sbls, tbot, ttop, color);

// Then annotate surfaces with face entity IDs for mouse selection:
// Surfaces at is=0 and is=1 are top/bottom faces
// Subsequent surfaces are side faces (matched to LINE_SEGMENT entities)
```

### GenerateForBoolean (src/groupmesh.cpp:182-210):
```cpp
template<class T>
void Group::GenerateForBoolean(T *prevs, T *thiss, T *outs, CombineAs how) {
    if(thiss->IsEmpty() || suppress) {
        outs->MakeFromCopyOf(prevs);  // no-op if nothing to contribute
        return;
    }
    switch(how) {
        case CombineAs::UNION:        outs->MakeFromUnionOf(prevs, thiss);      break;
        case CombineAs::DIFFERENCE:   outs->MakeFromDifferenceOf(prevs, thiss); break;
        case CombineAs::INTERSECTION: outs->MakeFromIntersectionOf(prevs, thiss); break;
        case CombineAs::ASSEMBLE:     outs->MakeFromAssemblyOf(prevs, thiss);   break;
    }
}
```

**The boolean is always templated**: works on either `SShell` (NURBS) or `SMesh` (triangles). If the group is `IsForcedToMesh()`, it falls back to triangle mesh booleans.

## 5. IsMeshGroup() (src/groupmesh.cpp:545-557)

```cpp
bool Group::IsMeshGroup() {
    switch(type) {
        case Group::Type::EXTRUDE:
        case Group::Type::LATHE:
        case Group::Type::REVOLVE:
        case Group::Type::HELIX:
        case Group::Type::ROTATE:
        case Group::Type::TRANSLATE:
            return true;
        default:
            return false;
    }
}
```

**CHAMFER and FILLET must return `true` from `IsMeshGroup()`** — they contribute solid geometry and their running shell needs to accumulate.

## 6. The RunningMeshGroup() Chain (src/groupmesh.cpp:531-543)

```cpp
Group *Group::RunningMeshGroup() const {
    if(type == Type::TRANSLATE || type == Type::ROTATE) {
        return SK.GetGroup(opA)->RunningMeshGroup();
    } else {
        return PreviousGroup();
    }
}
```

For a CHAMFER group, `RunningMeshGroup()` would return `PreviousGroup()` (the group being chamfered), just like EXTRUDE. This is correct — we want to boolean against the previous solid.

## 7. The MenuGroup() / Group Creation Path (src/group.cpp:70-290)

When a user selects a menu item (e.g., Sketch > New Extrude), `Group::MenuGroup(Command id)` is called:

1. Creates a new `Group g = {}`
2. Sets `g.type`, `g.opA = SS.GW.activeGroup`, `g.name`, etc.
3. Checks selection for required inputs
4. Calls `SK.group.AddAndAssignId(&g)` to register it
5. Calls `SS.GenerateAll()` to regenerate the entire chain
6. Activates the new group

**For CHAMFER/FILLET, the critical selection check would be**:
```cpp
case Command::GROUP_CHAMFER:
    // Option 1: Require selection of face entities (the faces to chamfer between)
    // Option 2: Operate on entire previous solid (apply to all edges, filter in UI)
    g.type = Type::CHAMFER;
    g.opA = SS.GW.activeGroup;  // target solid group
    g.valA = 1.0;               // default chamfer distance (1mm)
    g.name = "chamfer";
    break;
```

## 8. The Remap Table (src/group.cpp:850-865)

```cpp
hEntity Group::Remap(hEntity in, int copyNumber) {
    auto it = remap.find({ in, copyNumber });
    if(it == remap.end()) {
        remap.insert({ {in, copyNumber}, {(uint32_t)remap.size() + 1} });
    }
    return h.entity(it->second.v);
}
```

The remap table maps `(originalEntity, copyNumber)` pairs to new entity IDs within this group. This is used to generate stable entity handles for faces that can be used as constraint targets.

**For chamfer/fillet**, new REMAP_ constants would be needed:
```cpp
REMAP_CHAMFER_FACE  = 1011,  // for the new planar chamfer face
REMAP_FILLET_FACE   = 1012,  // for the new cylindrical fillet face
```

## 9. Entity Generation for Solid Groups

When an EXTRUDE group runs, it creates:
- `Entity::Type::FACE_XPROD` — for each lateral face (side wall), created by `MakeExtrusionLines()`
- `Entity::Type::FACE_NORMAL_PT` — for top and bottom faces, created by `MakeExtrusionTopBottomFaces()`

These entities ARE the "face handles" that users can click on for face selection, and that constraints can reference.

**For chamfer/fillet**, similar face-entity records would be created for the new surfaces. These would use `Entity::Type::FACE_NORMAL_PT` (or a new type if necessary).

## 10. The `predef` Struct's Role

The `predef` struct stores **geometric inputs** that define the operation:
- For EXTRUDE: `predef.entityB` = workplane handle (used to constrain extrusion direction)
- For REVOLVE/LATHE: `predef.origin` = axis point, `predef.entityB` = axis direction entity
- For WORKPLANE: `predef.q` = orientation quaternion, `predef.origin` = origin point

**For CHAMFER/FILLET, `predef` would store**:
- `predef.entityB` = a reference to a set of selected edges OR a face entity
- OR: `opA` = source group handle, and edge selection stored as a separate list

## 12. The Complete Extrude Pipeline (Concrete Example)

To understand where chamfer fits, trace an EXTRUDE operation end-to-end:

1. **User action**: Select workplane group, click Sketch > Extrude
2. **MenuGroup(GROUP_EXTRUDE)**:
   - `g.type = EXTRUDE`
   - `g.opA = activeGroup` (the sketch group)
   - `g.predef.entityB = activeWorkplane`
   - `g.subtype = ONE_SIDED`
   - Group added, `GenerateAll()` called
3. **GenerateAll()** calls, for this group:
   - `Group::Generate()` → creates params h.param(0..2) for extrusion vector, creates FACE entities
   - `Group::GenerateLoops()` → assembles bezier curves from source group (opA)
4. **GenerateShellAndMesh()** for the extrude group:
   - `thisShell.MakeFromExtrusionOf(bezierLoops, tbot, ttop, color)`
   - `thisShell.MergeCoincidentSurfaces()`
   - `GenerateForBoolean(prevShell, &thisShell, &runningShell, UNION)`
   - `runningShell` now contains the extruded solid
5. **GenerateDisplayItems()**:
   - `runningShell.TriangulateInto(&displayMesh)`
   - Build `displayOutlines` from sharp/emphasized edges

## 13. For Chamfer: The Analogous Pipeline

A CHAMFER group following an EXTRUDE would work as:

1. **User action**: Select an existing solid group, click Sketch > Chamfer Edge(s)
2. **MenuGroup(GROUP_CHAMFER)**:
   - `g.type = CHAMFER`
   - `g.opA = activeGroup` (the solid being chamfered)
   - `g.valA = 1.0` (default 1mm chamfer distance)
   - No 2D sketch needed — operates on solid directly
3. **Generate()**:
   - `AddParam(param, h.param(0), valA)` — the chamfer distance parameter
4. **GenerateShellAndMesh()**:
   - Access `SK.GetGroup(opA)->runningShell` as the source solid
   - Enumerate edges of the source shell (SCurve list)
   - For each selected edge: compute chamfer solid (a thin wedge)
   - `thisShell` = union of all chamfer wedges
   - `GenerateForBoolean(prevShell, &thisShell, &runningShell, DIFFERENCE)`
   - Result: runningShell = previous solid minus all chamfer wedges

## 14. Summary of Key Observations

1. **Group pipeline is linear and ordered**: each group's `runningShell` = boolean of its `thisShell` with the previous group's `runningShell`. Chamfer fits this model perfectly.

2. **No 2D sketch required**: CHAMFER/FILLET groups would be "sketch-less" groups (like LINKED groups in a sense) — they operate entirely on the 3D solid from `opA`.

3. **The `valA`/`valB`/`valC` fields** are readily available for chamfer/fillet parameters (distance, radius, etc.) without any struct changes.

4. **`meshCombine = DIFFERENCE`** for chamfer (cutting material away), `UNION` for additive fillet (adding material to fill concave edges).

5. **The remap table** enables stable entity IDs for faces — chamfer faces can be remapped and exposed for constraint attachment.

6. **`IsMeshGroup()` must be extended** to include CHAMFER/FILLET, otherwise the group won't contribute to the running solid.

7. **`GenerateEquations()`** can constrain the chamfer/fillet parameter if needed (e.g., to keep it equal to another dimension), but the simple case is just a stored scalar.

8. **Face entity generation** follows the EXTRUDE pattern: after generating `thisShell`, iterate over the new surfaces and create face handle entities for UI selection.
